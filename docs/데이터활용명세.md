# 데이터 활용 명세

제주 동네가게 AI Agent가 쓰는 데이터, 외부 API, 오픈소스를 정리했습니다.
모든 데이터는 전처리 후 SQLite 파일 하나(`data/processed/jeju.db`)에 들어가고, Agent 도구와 화면은 이 파일만 읽습니다.

---

## 2. 전처리

### 처리 순서

```
data/raw/<ID>/*.csv (허브 원본)
  │ build_store_db.py     780 → stores (가게 키, 업태 정리, 영업 여부)
  │ build_insight_db.py   583·490·502·504·495·1048·568·607·903·906 → 분석 테이블
  │ fetch_hub_api.py      API형 데이터 (583, 591, 592, 811)
  │ build_pois.py         811·784·591·592·568 → 관광 장소 429곳 + 월별 혼잡
  │ geocode_regions.py    읍면동 중심 좌표 42곳 (NCP Geocoding)
  │ geocode_stores.py     가게 좌표 (NCP Geocoding, 영업 중 20,954곳 중 20,941곳)
  │ check_naver.py        네이버 지도 등록 여부 (네이버 지역 검색)
  │ train_demand.py       방문 수요 예측 모델 학습·검증
  │ build_review_sentiment.py  오픈소스 감성 모델로 리뷰 판단
  ▼
data/processed/jeju.db  +  demand_model.joblib
```

### 데이터별 처리

| 데이터 | 처리 | 이유 |
|---|---|---|
| 780 음식점 | 상호+주소+인허가일로 가게 키 생성, 업태 이름 통일, 영업/폐업 구분, 해수욕장 계절음식점·마을 단체 인허가는 추천에서 제외 | 같은 가게 중복 방지, 한철 가게가 일반 식당처럼 추천되지 않게 |
| 780 갱신 | `sync_licenses.py`가 새 파일과 비교해 신규·폐업·상태 변경만 반영하고 `license_changes`에 기록 | 기존 가게 번호·네이버 확인 결과·좌표 유지 |
| 지역 연결 | 가게 주소는 법정동, 유동인구는 행정동이라 [regions.py](../app/data/regions.py) 대응표로 연결. 리(里) 이름은 가게 지번 주소로 읍·면을 찾음 | 영업 중 가게 전부 연결 |
| 583 유동인구 | 하루 누적 집계값이라 사람 수가 아니라 구성비·동네 평균 대비 비율로만 사용 | 값의 의미를 넘겨 해석하지 않기 (결정 D-04) |
| 490 + 502 | 2019년 시간대 비율 × (최근 12개월 카드 / 2019 카드) 보정 | 코로나 기간 왜곡을 피하고 최근 흐름 반영 (결정 D-01) |
| 504 | 공휴일 제외, 요일 수로 나눈 하루 평균 | 요일 계수 |
| 1048 | 음식점·주점 업종만 사용 | 식당 손님이 도민인지 관광객인지 |
| 568 와이파이 | 장소명 뒤의 AP 번호를 지우고 장소 단위로 합산, 숫자 오타 정리 | 같은 장소의 여러 공유기 합치기 |
| 607 | 지구 유형별 시간대 비율만 사용 | 오래된 자료라 절대값은 쓰지 않음 |
| 903 리뷰 | 작성자 이름·등급·사진 주소 삭제. 맛·친절·가격·주차·대기 등 요인 단어와 긍정·부정 표현으로 절 단위 분류 | 개인정보 제거, 같은 입력이면 같은 결과 |
| 903 감성 | 규칙 분류에 더해 오픈소스 KoELECTRA 감성 모델로 5,309개 절을 미리 판단해 `review_aspects`에 저장 (규칙과 일치율 90%) | 실행 중 GPU 없이 모델 결과 사용 |
| 인허가일 | '개업 N년'이 아니라 '인허가 기준 N년'으로 표시 | 주인·상호가 바뀌어도 인허가일이 이어질 수 있음 |

### 의사결정 모델

| 모델 | 입력 데이터 | 방법 | 검증 |
|---|---|---|---|
| 방문 수요 예측 | 583 (요일·공휴일·연휴·계절·동네) | scikit-learn HistGradientBoosting | 2025-08~2026-02 학습, 2026-03~04 검증: 오차 18.9% (요일 평균 22.8%), 혼잡 등급 일치 59.4% (36.9%). 공휴일은 일요일 패턴으로 대체 |
| 혼잡 등급 | 수요 예측 × 시간대 비율(490·502) × 요일 계수(504) | 제주 전체 분포의 구간으로 한산/보통/붐빔 | 실시간 아님을 항상 표시 |
| 관광객 추천 | 혼잡 등급, 생활권 과밀도(583), 네이버 등록 여부, 인허가 햇수(780) | 다기준 가중 점수 (덜 붐빔 .35 · 생활권 여유 .25 · 숨은 가게 .20 · 오래된 가게 .20) | 같은 입력이면 같은 순위, 기준별 점수 공개 |

## 5. 빅데이터센터 PC 실행

- 처리된 `jeju.db`와 수요 예측 모델 파일이 있으면 원본 데이터 없이 바로 실행됩니다. 원본부터 다시 만들려면 허브에서 같은 데이터를 받아 2절 순서대로 실행합니다.
- 센터 안에서만 쓸 수 있는 반출 불가 데이터는 쓰지 않았습니다. 데이터 읽기는 `app/data/db.py` 한 곳에 모여 있어서, 센터 데이터를 쓰려면 이 부분만 바꾸면 됩니다.
- GPU는 필요 없습니다. 인터넷 연결은 Claude·네이버·Gemini API 호출에 필요합니다.
